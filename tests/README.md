# Тестовая документация

Документ описывает ручную проверку frontend и backend приложения Notes. Автоматический тестовый runner пока не подключён, поэтому каждый сценарий выполняется через браузер, Swagger или `curl`.

## 1. Подготовка

### Требования

- Node.js 20 или новее;
- npm;
- .NET SDK 10;
- PostgreSQL;
- настроенный файл `backend/NotesApp.Api/.env`.

### Запуск backend

Из корня проекта:

```bash
cd backend/NotesApp.Api
dotnet run --launch-profile http
```

Ожидаемый адрес API: `http://localhost:5165`.

Если порт уже занят, сначала остановите старый экземпляр:

```bash
lsof -t -iTCP:5165 -sTCP:LISTEN | xargs -r kill
```

### Запуск frontend

Во втором терминале из корня проекта:

```bash
npm install
npm run dev
```

Откройте адрес Vite, например `http://localhost:5173`. В Codespaces открывайте forwarded-порт frontend. Запросы `/api/*` проксируются Vite на backend `5165`.

### Быстрая проверка API

```bash
curl -i http://localhost:5165/swagger/index.html
```

Ожидаемый результат: `HTTP/1.1 200 OK`.

## 2. Проверки сборки и качества

### Production-сборка

```bash
npm run build
```

Проверяет TypeScript, JSX и production-сборку Vite. Ожидается завершение без ошибок.

### ESLint

```bash
npm run lint
```

Проверяет frontend-код правилами ESLint. Ожидается отсутствие ошибок и предупреждений, связанных с изменённым кодом.

### Сборка backend

```bash
cd backend/NotesApp.Api
dotnet build
```

Проверяет компиляцию ASP.NET Core API.

## 3. Авторизация и регистрация

### Регистрация нового пользователя

1. Откройте `/register`.
2. Введите новый email.
3. Введите пароль длиной 8 или более символов.
4. Повторите пароль точно так же.
5. Нажмите «Создать аккаунт».

Ожидаемый результат:

- отправляется `POST /api/Auth/register`;
- после ответа `200 OK` access token сохраняется в `localStorage` под ключом `access_token`,
  а refresh token приходит в `HttpOnly` cookie;
- пользователь перенаправляется на `/MainNotes`;
- отображается авторизованный header с аватаром профиля.

### Пустые обязательные поля

1. Откройте `/register`.
2. Оставьте email или пароль пустым.
3. Нажмите кнопку регистрации.

Ожидаемый результат: браузерная валидация `required` не отправляет запрос.

### Слишком короткий пароль

1. Откройте `/register`.
2. Введите пароль из 7 символов.
3. Заполните подтверждение и отправьте форму.

Ожидаемый результат: отображается сообщение «Пароль должен содержать не менее 8 символов», API не вызывается.

### Несовпадающие пароли

1. Введите пароль длиной не менее 8 символов.
2. В поле подтверждения введите другое значение.
3. Отправьте форму.

Ожидаемый результат: отображается сообщение «Пароли не совпадают», API не вызывается.

### Регистрация существующего email

1. Зарегистрируйте пользователя.
2. Повторите регистрацию с тем же email.

Ожидаемый результат: API возвращает `409 Conflict`, frontend показывает сообщение о существующем пользователе и не выполняет переход.

### Вход с корректными данными

1. Откройте `/login`.
2. Введите email и пароль зарегистрированного пользователя.
3. Нажмите «Войти».

Ожидаемый результат:

- отправляется `POST /api/Auth/login`;
- JWT сохраняется через `setToken`;
- выполняется переход на `/MainNotes`.

### Вход с неверными данными

1. Откройте `/login`.
2. Введите неверный email или пароль.
3. Отправьте форму.

Ожидаемый результат: API возвращает `401 Unauthorized`, показывается сообщение об ошибке, переход на `/MainNotes` не выполняется.

### Защита маршрута

1. Удалите `access_token` из Application Storage браузера.
2. Откройте `/MainNotes` напрямую.

Ожидаемый результат: `ProtectedRoute` перенаправляет пользователя на `/login`.

## 4. ProfilePopover

### Открытие меню профиля

1. Авторизуйтесь.
2. Нажмите на аватар в header.

Ожидаемый результат: открывается `ProfilePopover`, расположенный рядом с кнопкой профиля.

### Закрытие по клику вне меню

1. Откройте меню профиля.
2. Нажмите в любом месте вне popover.

Ожидаемый результат: popover закрывается.

### Закрытие клавишей Escape

1. Откройте меню профиля.
2. Нажмите `Escape`.

Ожидаемый результат: popover закрывается.

### Закрытие при смене URL

1. Откройте меню профиля.
2. Перейдите на другой маршрут через navigation или вручную измените URL.

Ожидаемый результат: popover закрывается через `closePopover`, состояние не сохраняется на новом маршруте.

### Выход из аккаунта

1. Откройте меню профиля.
2. Нажмите «Выйти из аккаунта».

Ожидаемый результат:

- вызывается `removeToken`;
- access token удаляется из `localStorage`, refresh cookie очищается backend;
- выполняется переход на `/login`;
- защищённые страницы снова недоступны.

## 5. Responsive UI

### Burger-меню

1. Откройте `/MainNotes` на viewport уже `1023px` или меньше.
2. Нажмите кнопку меню в header.

Ожидаемый результат:

- открывается drawer sidebar с плавным выездом слева;
- фон затемняется и блокирует прокрутку страницы;
- клик по overlay, `Escape` или пункту меню закрывает drawer.

### ProfilePopover на мобильном

1. Откройте приложение на мобильной ширине.
2. Нажмите аватар пользователя.

Ожидаемый результат: popover занимает ширину экрана с боковыми отступами и
плавно появляется без горизонтального overflow.

### Заметки и пагинация

1. Откройте страницу с несколькими заметками.
2. Перейдите на следующую страницу через pagination.
3. Откройте меню карточки и выберите удаление.

Ожидаемый результат:

- карточки появляются с последовательной анимацией;
- кнопки pagination доступны на мобильной ширине;
- открывается Zustand modal подтверждения удаления;
- после подтверждения список и счётчики sidebar обновляются.

## 6. API Auth endpoints

### Регистрация через curl

```bash
curl -i -X POST http://localhost:5165/api/Auth/register \
	-H 'Content-Type: application/json' \
	-d '{"email":"manual-test@example.com","password":"password123"}'
```

Ожидаемые ответы:

- `200 OK` и JSON с полем `token` — пользователь создан;
- `409 Conflict` — email уже зарегистрирован.

### Вход через curl

```bash
curl -i -X POST http://localhost:5165/api/Auth/login \
	-H 'Content-Type: application/json' \
	-d '{"email":"manual-test@example.com","password":"password123"}'
```

Ожидаемые ответы:

- `200 OK` и JSON с полем `token` — вход выполнен;
- `401 Unauthorized` — неверные данные.

## 7. Notes API

Для этих сценариев сначала получите JWT через регистрацию или вход и замените `<jwt>` на его значение.

### Получение заметок

```bash
curl -i http://localhost:5165/api/Notes \
	-H 'Authorization: Bearer <jwt>'
```

Ожидается `200 OK` и список заметок текущего пользователя.

### Создание заметки

```bash
curl -i -X POST http://localhost:5165/api/Notes \
	-H 'Authorization: Bearer <jwt>' \
	-H 'Content-Type: application/json' \
	-d '{"title":"Тестовая заметка","content":"Проверка API"}'
```

Ожидается успешный ответ с созданной заметкой.

### Обновление заметки

```bash
curl -i -X PUT http://localhost:5165/api/Notes/<id> \
	-H 'Authorization: Bearer <jwt>' \
	-H 'Content-Type: application/json' \
	-d '{"title":"Обновлённая заметка","content":"Новый текст"}'
```

Ожидается успешное обновление заметки.

### Удаление заметки

```bash
curl -i -X DELETE http://localhost:5165/api/Notes/<id> \
	-H 'Authorization: Bearer <jwt>'
```

Ожидается `204 No Content`.

### Запрос без JWT

Повторите любой защищённый запрос без заголовка `Authorization`.

Ожидаемый результат: `401 Unauthorized`.

## 8. Критерии готовности

- `npm run build` завершается успешно;
- `dotnet build` завершается успешно;
- регистрация создаёт пользователя и сохраняет JWT;
- вход принимает только корректные данные;
- пароль короче 8 символов и несовпадающее подтверждение блокируют отправку;
- `ProtectedRoute` закрывает `/MainNotes` без JWT;
- ProfilePopover открывается и закрывается во всех описанных сценариях;
- burger drawer работает на мобильной ширине и закрывается по overlay/Escape;
- deletion modal подтверждает удаление и обновляет список заметок;
- выход удаляет JWT;
- API Notes не отдаёт данные без авторизации.
